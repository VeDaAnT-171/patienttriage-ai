Waiting Room Monitoring

"Start live monitoring" uses your webcam as a stand-in for waiting-room CCTV: it captures a frame automatically every 20 seconds (compressed for demo purposes - a real deployment would check every few minutes, not seconds) and sends it to Claude's vision model for change-detection only, never diagnosis. You can also capture a single photo manually, or use "Quick simulate" if camera access isn't available. A nurse always verifies before anything changes.

Demo note: only use a camera/photo you have the right to use (e.g. yourself, with consent). This panel demonstrates the workflow, not real patient monitoring.

Bed Board

Tracks every ED bed's real-time status. "Call to bed" from the queue assigns a patient to a specific empty bed; "Discharge / free bed" here releases it immediately, so the board always reflects which beds are actually available right now.

About this prototype. The intake form and deterministic rule engine run fully client-side. Acuity scoring and photo/frame analysis both call Claude (Anthropic's LLM) live - text reasoning for intake scoring, vision reasoning for waiting-room checks. Inside the Claude.ai artifact preview this works without setup; standalone, paste your own API key in Settings above. If no call succeeds, the app falls back to a deterministic NEWS2-inspired heuristic (structured scoring) or a manual "quick simulate" path (waiting-room checks) so the tool stays usable and demoable offline - the fallback's confidence score now varies with how much structured data is available and how strong the triggered indicators are, rather than a fixed number. See the README for the full explanation of the ML/AI approach used here versus a production target architecture.
